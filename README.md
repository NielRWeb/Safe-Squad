# SAFE SQUAD — Child Protection Game Hub

A mobile-first, browser-based educational game hub for **High School / Senior High School**
students. **Seven** original cartoon mini-games teach child-protection topics: online safety,
personal boundaries, bullying, trusted adults, recognising unsafe situations and asking for help.

Built with **Vite + TypeScript + SVG/Canvas/CSS**. No backend, no database, no tracking,
no third-party runtime dependencies, and **all artwork, characters, music and sound effects
are original and generated by this project's own code**.

## ⭐ The questionnaire (the important bit)

**All educational content lives in one file:**

```
src/data/questions.ts
```

It holds the **official SAFE SQUAD questionnaire**: 7 categories × 5 YES/NO questions =
**35 questions**, each with its official explanation, plus one official completion message per
category.

| # | Category | Questions |
|---|----------|-----------|
| 1 | Physical Abuse — Corporal Punishment | 5 |
| 2 | Physical Abuse — Bullying or Peer Abuse | 5 |
| 3 | Psychological Abuse — Child Abuse | 5 |
| 4 | Psychological Abuse — Discrimination Against Children | 5 |
| 5 | Psychological Abuse — Child Exploitation | 5 |
| 6 | Psychological Abuse — Violence Against Children | 5 |
| 7 | Psychological Abuse — Bullying or Peer Abuse | 5 |

**How the games use it:** every round of every mini-game picks **one random category** and plays
its five questions in random order (`QuizSession` in `src/core/quiz.ts`). After each answer the
game shows that question's official explanation, and the completion screen shows that category's
official completion message — so the guidance always matches the questions that were played.

Editing: keep ids unique, keep `correct` as `'YES' | 'NO'`, and keep five questions per category
(one category = one round). Nothing else in the codebase hard-codes a question.

## The seven games

| # | Game | Official mechanic |
|---|------|-------------------|
| 1 | **Don't Make the Baby Cry** | You are the mother carrying the baby. Each YES/NO question is **timed**; a wrong answer *or* a timeout costs one of **3 chances that persist for the whole round** — 1st mistake the baby cries softly, 2nd it cries louder, 3rd it has a tantrum and the game ends. Finish all five questions with chances left to win. |
| 2 | **Attach the Missing Puzzle** | Each question corresponds to a puzzle piece. A correct YES/NO answer earns the piece; the student then **manually drags it into place** (pieces never place themselves). A wrong answer earns nothing, shows the official explanation plus a tip, and the same question returns. Completing the picture wins. |
| 3 | **Fact or Fall** | The car drives to a fork where a YES/NO question appears: **LEFT = YES, RIGHT = NO**. The correct road continues the journey; the wrong road crashes the car and costs one of **3 chances**. The run ends at the destination or when the chances are gone. Scenery is never placed on either road, so the environment cannot reveal the answer. |
| 4 | **Save Your Hearts** | Player and opponent both start with **3 hearts**. Correct answer → opponent loses a heart; wrong answer → the player loses one. 3 → 2 → 1 → 0; whoever hits 0 first loses. |
| 5 | **Choose & Escape** | **No question popup at all.** The arcade maze appears immediately and the statement is shown as a thin strip above it; the **YES and NO portals inside the maze are the answer interface** — the portal the player drives into *is* their answer, which is then evaluated and explained. **Three enemies move and chase from the first second** (four-way grid movement, Pac-Man side portals, ghosts slower than the player). Being caught sends the player back to the entrance with a tip. |
| 6 | **Save the Princess** | Original platform hero across three levels with **3 hearts**. Question-mark blocks are the only source of questions: a correct answer turns the block into a star and opens the level gate, a wrong answer costs a heart and returns the hero to the last checkpoint. Clear all levels to save the princess. |
| 7 | **Bingo** | 5×5 board of 25 closed blocks that **all look identical** — nothing highlights, glows or outlines the correct boxes, and the pattern name stays hidden while the round is running. A **horizontal, vertical or diagonal** star pattern is generated at the start and **regenerated on every retry**. Breaking a block reveals an empty square or a star; a star is only collected after answering its YES/NO question correctly. Completing the hidden pattern is a BINGO (the pattern is revealed only once the round ends). |

Every game plays one category (five questions) per round. Two safety nets are shared by all seven:

* **Mistake coach** — after 3 wrong answers in the current round a friendly popup appears with an
  educational tip and a shortcut to How to Play. It never reveals the answer and never spams: it
  fires when the threshold is crossed, then only after another 3 mistakes. The counter belongs to
  the round, so mistakes never carry over between mini-games.
* **Return to Hub confirmation** — leaving a round in progress asks "Return to Hub? Your progress
  in this round will be lost", with large, full-width buttons on phones. Cancel keeps the game
  exactly as it was; confirming cleans up the scene, its animation loop and its audio.

## Shared systems

| System | File | Used by |
| ------ | ---- | ------- |
| Question rounds (one category, shuffled, scored) | `src/core/quiz.ts` → `QuizSession` | all 7 games |
| HUD + progress (`Question n / 5`, chances, hearts, level, pattern) | `src/core/ui.ts` → `Hud` | all 7 games |
| Question overlay (YES/NO) | `src/core/ui.ts` → `QuestionOverlay` | hearts, princess, bingo, maze |
| Feedback banner with official explanations | `src/core/ui.ts` → `Feedback` | all 7 games |
| Tips + 3-mistake coach | `src/core/ui.ts` → `TipBubble`, `MistakeCoach` | all 7 games |
| Completion screen with the official category message | `src/core/ui.ts` → `buildCompletion` | all 7 games |
| Scene routing, confirmation dialogs, modal cleanup | `src/core/router.ts`, `src/core/modal.ts` | all |
| Scene-scoped timers (no stale alerts after retry) | `src/utils/dom.ts` → `TimerPool` | all 7 games |
| Audio (music + SFX) | `src/core/audio.ts` | all |

**Retry = a completely fresh scene.** Replay/Return-to-Hub tear the scene down: timers cleared,
coach disposed (it can only ever have one alert open), overlays/feedback hidden, every modal
closed — and each game also calls `closeAllModals()` as it starts, so no dialog can survive into a
new round no matter how it was entered. The router then rebuilds the game from scratch (new
category, new board, reset counters).

## Audio

`src/core/audio.ts` is a small synthesiser built on the Web Audio API:

* eight original background loops (hub, nursery lullaby, puzzle plucks, driving groove,
  battle march, maze creep, hero adventure, bingo sparkle)
* cartoon SFX: buttons, correct/incorrect, snap, baby coo/fuss/cry/tantrum, mother gasp,
  engine, skid, crash, flat tyre, fanfare, attack, hurt, jump, coin, box-open, empty,
  victory, defeat
* mute music / mute SFX / master volume, all saved to `localStorage`
* browsers block autoplay, so audio unlocks automatically on the first tap, click or keypress

Want to use your own recordings instead? Put files in `assets/audio/`, import them in
`src/audio/manifest.ts` and map them to a sound name — anything mapped replaces the generated
version, everything else keeps working.

## Accessibility & mobile notes

* Semantic HTML, `aria-label`s on every icon button, `role="status"` live regions for feedback
* Correct/incorrect is communicated by icon + text + sound, never by colour alone
* Visible focus rings; keyboard shortcuts: `Y` / `N` (Baby Cry), `←` / `→` (Fact or Fall),
  arrows/WASD (Choose & Escape), arrows/A-D + Space (Save the Princess), `Enter` on a focused
  puzzle piece attaches it, `Esc` closes dialogs
* Every action game also has finger-sized on-screen controls (maze D-pad, run/jump pad)
* **Classroom assist mode**: open Save the Princess with `?assist=1` in the URL and falls or
  critters send the student back to the checkpoint without costing a life, so students who
  struggle with platforming still reach every question
* **Classroom demo shortcut**: `?level=2` or `?level=3` starts Save the Princess on that level,
  handy when demonstrating the castle ending without replaying the whole world
* **No stale dialogs**: every scene owns a `TimerPool` and disposes its `MistakeCoach`, so a
  pending alert from a finished round can never appear on top of a freshly restarted game
* Touch targets are ≥ 46 px, no hover-only interactions, no horizontal scrolling
* Safe-area insets for notched phones; layouts rearrange (not just shrink) between
  small phones, large phones, tablets, laptops and desktops
* `prefers-reduced-motion` disables animation for students who need it

## Final polish pass — mobile-first hardening

This pass changed no game rules, questions, enemy behaviour, controls, scoring
or lives. It fixed layout/perf defects found by measuring the running app.

### 1. Choose & Escape statement container
The educational statement was floating text with no styling at all
(`.maze__strip` / `.maze__statement` / `.maze__topic` had **no CSS rules**).
It now sits in a rounded, semi-transparent white card with padding, a soft
border and shadow, sized by its own content so long statements wrap instead of
overflowing. The card is above the maze, in normal flow, and never covers the
board.

### 2. Bugs fixed (all found by measurement, all verified in the browser)
- HUD sound/help buttons were squashed to **17x46px** on a 320px screen
  (`.icon-btn` had no `flex-shrink: 0`). Now never below 40x40.
- Inline icon SVGs have a 64-unit viewBox and no intrinsic CSS size, so any
  unconstrained button rendered them at 64px+ — **163px** on the 320px hub, and
  it inflated the HUD to **104px** in landscape, overlapping the game stage.
  Fixed with `.btn > svg`, `.hud__back svg` and `.gcard__play svg` rules.
- `.hearts__name` (`white-space: nowrap`, no max-width) pushed the battle arena
  past the right edge on every portrait phone.
- `.princess__status` and `.toast` were centred with `left: 50%`, which caps an
  absolutely positioned shrink-to-fit box at half the screen — the level/star
  pill and short toasts wrapped onto stacked lines. Now centred with auto
  margins and `width: max-content`.
- The maze canvas had a `Math.max(120, ...)` height floor, so in landscape a
  120px canvas sat inside a 42px wrapper and spilled over the D-pad.
- The maze short-screen `@media` rules were being beaten on source order by the
  base `.maze__strip` block, so landscape never got its compact layout.
- Canvas sizing used the fractional `getBoundingClientRect()` and rounded up,
  putting the canvas a half pixel past the viewport (sideways page scroll).
- The HUD progress label ellipsed away the "chances 3/3" part on phones; it now
  wraps to two lines with `--hud-h` growing to match.
- The maze's round-start toast sat on top of the maze and, at 320px, on top of
  the D-pad itself. It is now part of the banner, in normal flow.
- Stale How-to-Play text still described the removed pre-maze question pop-up.

### 3. Mobile performance (no visual style changed)
- `canvasDpr()` in `src/utils/dom.ts` caps the canvas backing store at 1.5x on
  coarse-pointer (touch) devices; mouse/desktop still render up to 2x. This was
  the dominant cost — a 390x844 screen at DPR 2 is 1.3M pixels per frame.
- The three canvas games no longer measure layout every frame; a ResizeObserver
  sets a `sizeDirty` flag instead (this also removed a forced synchronous
  layout per frame per game).
- Fact or Fall skips repainting when its scene is unchanged (the whole time the
  player is reading a question). Its DOM car/driver animations keep playing.
- Looping decorative CSS animations pause while a modal covers the screen
  (`body.has-modal`), which is invisible to the player and free to undo.

Measured at 4x CPU throttle, 390x844:
Fact or Fall **16 -> 41 fps**, Choose & Escape **44 -> 60 fps**,
Save the Princess **25 -> 47 fps**. No rAF, interval, listener or DOM leaks
across three full passes through all seven games.

### 4. Touch and gestures
`.game` now sets `touch-action: manipulation` and `overscroll-behavior: none`
(no double-tap zoom, no pull-to-refresh mid-game); canvases and D-pads keep
`touch-action: none`. The maze canvas clears its swipe origin on
`pointercancel`. Existing pointer handling in every game was verified working
by real touch taps rather than mouse clicks.
